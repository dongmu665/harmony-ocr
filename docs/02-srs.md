# Software Requirements Specification

## 1. 引言

本文定义基于 HarmonyOS 的智能图片文字识别与云端历史管理系统的软件需求、版本边界和安全约束。仓库中的 HarmonyOS 客户端、Spring Boot 服务端、Web 管理台与部署模板均以这些需求为实现依据。

## 2. 系统目标

- 提供 HarmonyOS 移动端 OCR 主流程。
- 提供用户账号、历史记录和云端同步能力。
- 支持安全、隐私、可测试、可部署的后端服务演进。
- 支持 BYOK AI 与后端 AI 代理，并保持用户授权、密钥加密和第三方数据外发边界清晰。

## 3. 用户角色

- 游客用户: 可使用本地 OCR 和临时本地记录能力，无法使用云端历史同步。
- 登录用户: 可使用云端历史同步、账号管理、数据删除和注销能力。
- 管理员角色: 用于管理用户、OCR 记录元数据、反馈、会员额度和审计数据；所有管理接口必须单独校验管理员身份。

## 4. 功能需求

- 账号: 注册、登录、退出、刷新 Token、修改资料、修改密码、注销账号。
- OCR: 拍照识别、相册识别、图片预览、裁剪、扫描型 PDF 输入识别、识别中状态、结果展示。
- 文本: 编辑、复制、格式清理、保存。
- 历史: 创建、列表、详情、删除、收藏、搜索、云端同步。
- 文件: 上传图片和生产导出文件应进入对象存储，数据库只保存 object key 和元数据。当前导出任务实现仍把生成内容保存在 MySQL，生产部署前必须迁移到对象存储并增加过期清理。
- 反馈: 用户可提交反馈；管理端可在不暴露反馈正文和联系方式的列表中查看元数据并更新处理状态。
- AI: 客户端通过受保护 API 提交用户 Provider 配置，后端加密保存 API Key 并代理调用；任何 OCR 文本外发前都必须取得用户明确同意。

## 5. 非功能需求

- 可维护性: 模块边界清晰，文档先行。
- 可扩展性: 支持 OCR、AI、同步和导出能力逐步扩展。
- 可用性: 弱网下应给出明确状态和重试入口。
- 性能: OCR 主流程需记录耗时并避免阻塞 UI。
- 可观测性: 后端必须提供脱敏日志、管理操作审计和稳定错误码，不记录 OCR 全文、凭据或完整外部请求。

## 6. 安全需求

- 密码只保存 BCrypt 哈希。
- JWT secret、数据库密码、MinIO 密钥来自环境变量或密钥管理系统。
- 受保护 API 必须验证 Access Token。
- 用户资源必须执行 ownership check。
- Refresh Token 需要哈希或可撤销存储，不得明文长期保存。
- 文件上传必须校验类型和大小。
- V2.0 后端代理如支持自定义 Base URL，必须实现 SSRF 防护。

## 7. 隐私需求

- 用户协议和隐私政策必须在注册、设置和相关入口可访问。
- 第三方 AI 调用前必须提示用户，并说明 OCR 文本将发送到第三方提供商。
- 隐私敏感 OCR 文本未经同意不得发送到第三方。
- 用户注销时必须删除或匿名化个人数据。
- API Key 不得记录到日志或完整返回给客户端。

## 8. 数据需求

- MySQL 保存用户、Token、设备、记录、文本块、文件对象、审计日志和反馈。
- 图片不进入 MySQL，只保存 MinIO object key。
- 识别记录、文本块、文件对象必须包含 `user_id` 或可追溯的归属关系。
- 删除优先软删除，账号注销需要执行数据删除或匿名化策略。

## 9. 异常场景

- 注册用户名或手机号重复。
- 登录密码错误或账号已注销。
- Access Token 过期，Refresh Token 无效或已撤销。
- OCR 失败、超时、图片格式不支持、扫描型 PDF 损坏、加密、页数超限或额度不足。
- 上传文件超过大小限制或 MIME 类型不合法。
- 弱网导致同步失败。
- 用户访问他人记录。
- AI API 超时、认证失败、Base URL 不合法或隐私授权缺失。

## 10. 系统边界

- V1.0 不实现后端增强 OCR、会员系统、Web 管理后台和后端 AI 代理。
- 游客模式与登录模式的差异: 游客只能使用本地能力，登录用户可使用云端历史同步和账号级数据管理。
- 当前 BYOK 配置由后端加密托管，API Key 只能通过 HTTPS 受保护接口提交且不得明文返回；纯端侧安全存储模式尚未实现。
- V2.0 后端代理模式才考虑后端加密保存 API Key。

## 11. V1.0 需求详情

V1.0 必须覆盖用户注册、用户登录、退出登录、拍照识别、相册识别、图片预览、图片裁剪、OCR 文字识别、识别结果展示、文本编辑、文本复制、文本格式清理、保存历史记录、查看历史记录、查看历史详情、删除历史记录、收藏记录、搜索历史记录、云端同步历史记录、用户协议、隐私政策、账号注销和数据删除。

### 11.1 账号与认证

- 注册必须要求用户确认用户协议和隐私政策。
- 登录成功后签发 Access Token 和 Refresh Token。
- 退出登录必须撤销当前 Refresh Token。
- 受保护接口必须校验 Access Token。
- Refresh Token 必须可撤销，不得明文长期保存。

### 11.2 OCR 与图片流程

- 用户可从相机或相册获取图片。
- OCR 前必须支持图片预览和裁剪。
- OCR 失败、超时或图片格式不支持时必须给出明确错误状态。
- 端侧 OCR 优先使用 HarmonyOS CoreVisionKit；端侧运行时不可用时可调用已配置的后端真实 OCR Provider。两条路径都必须返回明确的失败、超时和不支持格式状态。

### 11.3 文本处理

- 识别结果必须支持展示、编辑、复制和格式清理。
- 格式清理在 V1.0 只做基础空格、换行和简单噪声处理。

### 11.4 历史记录与同步

- 保存历史记录时必须绑定当前用户；游客模式只能保存本地临时记录。
- 登录用户可查看历史列表、历史详情、删除记录、收藏记录和搜索历史记录。
- 云端同步仅对登录用户开放。
- V1.0 采用服务端为准的最小同步策略，支持按 `updated_at` 增量拉取和按 `deleted_at` 同步软删除。
- 后端不得允许用户访问、修改或删除其他用户的记录。

### 11.5 隐私、注销与数据删除

- 用户协议和隐私政策必须在注册、设置和相关页面可访问。
- 账号注销必须撤销用户所有 Refresh Token。
- 账号注销后，个人数据必须删除或匿名化。
- OCR 文本、历史记录、文件对象和设备信息必须纳入删除或匿名化策略。
- 审计日志可保留安全必要信息，但应去标识化或避免保留可直接识别个人的信息。

## 12. V1.1 需求详情

V1.1 包含导出 TXT、分享识别文本、按日期筛选历史、按来源筛选历史、识别耗时显示、默认识别语言设置、是否自动清理格式设置、清理本地缓存和用户反馈。

V1.1 描述在 V1.0 基础流程之上的体验增强，其回归测试不得削弱 V1.0 的认证、OCR、历史记录和数据删除边界。

## 13. V1.2 需求详情

V1.2 Advanced OCR Productivity 首批包含历史标签 / 分类、高级历史搜索增强和 Markdown 导出。历史标签必须按当前登录用户隔离，同一用户下标签名不重复，记录绑定标签前必须校验 record 和 tag 均属于当前用户。高级历史搜索必须支持关键词、日期、来源、收藏、标签、OCR 引擎、分页和白名单排序组合，不得泄露其他用户记录。Markdown 导出只做轻量结构化文本导出，不引入 marker 依赖，不记录导出全文，不记录完整路径。

V1.2 还包含批量图片识别、批量导出、PDF 导出、文本转语音 TTS、多语言识别、识别置信度提示、低置信度文本标注、图片旋转、图片去噪和图片倾斜校正。批量 OCR、置信度 / 识别框字段和 Share-to-App 图片入口必须继续遵守用户资源隔离、文件校验和隐私最小化原则。

扫描型 PDF 输入 OCR 已作为独立后端链路和 ArkUI 接入实现。能力范围为上传 `application/pdf`、校验 PDF 签名/大小/页数/加密状态、内存逐页渲染并调用现有 OCR Provider、返回页级状态和聚合文本；不实现 PDF/A、复杂版式还原、表格识别、OCRmyPDF、对象存储 PDF 持久化或 searchable PDF 输入反解析。

V1.2 是建立在 V1.0 主流程之上的可选增强，相关能力失败时不得破坏基础 OCR、历史记录和账号流程。

## 14. BYOK AI 需求详情

BYOK AI 包含自定义 AI 供应商配置、用户自带 API Key、供应商名称、API Base URL、模型名称、启用/停用配置、测试 API 连接、OCR 文本 AI 纠错、摘要、翻译、智能排版、转 Markdown、默认配置和删除配置。当前客户端在创建或更新配置时通过受保护 API 把 API Key 发送给后端；后端使用 AES-GCM 加密保存，后续响应不返回明文。生产环境必须使用 HTTPS，并由运行时环境或 KMS 提供后端主密钥。

当前仓库没有实现设备侧 HUKS/KeyStore BYOK 存储，不得把后端托管模式描述为纯端侧密钥方案。若未来增加纯端侧模式，必须与后端托管配置明确区分，并继续满足脱敏响应、日志保护和用户授权要求。

## 15. V2.0 需求

当前仓库已经实现后端 OCR Provider 接口、扫描型 PDF 与批量 OCR、会员额度、Web 管理台、AI 摘要与翻译、用户 Provider 配置加密存储和后端 AI 代理。代码包含多 Provider 顺序切换 contract 与自动化测试，但默认 Provider 条件和部署模板只启用单一 OCR/AI Provider；可配置的生产 Provider chain 仍属于后续范围。PaddleOCR 独立服务、表格识别、完整可搜索 PDF 工作流、云端文件夹、复杂多设备冲突合并、生产级任务队列、支付结算和 KMS 集成也仍未包含。

V2.0 能力必须保持可选，未配置外部 OCR、AI Provider 或生产密钥管理设施时，V1.0 基础流程仍应可独立运行。
