# Product Requirements Document

## 1. 产品目标

建设一款可上线、可维护、可扩展的 HarmonyOS OCR 产品，覆盖图片文字识别、文本处理、历史管理、云端同步、用户账号与后续 AI 增强。

## 2. 用户画像

- 日常用户: 偶尔从图片、截图、票据中提取文本。
- 办公用户: 频繁处理文档、会议资料、公告和合同片段。
- 学习用户: 提取书页、课堂板书、讲义和资料截图。
- 进阶用户: 希望使用 BYOK AI 对 OCR 文本进行纠错、摘要、翻译和排版。

## 3. 用户场景

- 用户拍照识别纸质文本，清理格式后复制到聊天或文档。
- 用户从相册选择截图，识别后保存到历史记录。
- 登录用户在云端同步历史记录，并在新设备恢复查看。
- 用户注销账号时要求删除或匿名化个人数据。
- 进阶用户可配置自带 API Key，在明确隐私提示后对 OCR 文本调用第三方 AI。

## 4. 功能总览

产品功能按核心流程、体验增强、进阶 OCR 与 BYOK AI、可选平台与长期扩展组织。任何开发任务都必须先落入本 PRD 或 SRS。

## 10. 功能优先级

- P0: 核心产品必需能力，涉及主流程、账号、安全、隐私和数据完整性。
- P1: 上线后优先增强能力，改善体验或形成差异化竞争力。
- P2: 商业化、规模化、复杂 AI 或后台能力，需专项设计后实施。

核心产品能力矩阵中的 23 项功能均属于上线范围，不得在后端基础设计、API 设计或测试计划中降级为“可选实现”。体验、进阶和可选平台能力只有在用户明确要求或核心流程稳定后才能进入实现。

## 11. 用户故事

- 作为用户，我希望拍照后快速得到可编辑文字，以便复制到其他应用。
- 作为用户，我希望从相册图片识别文字，以便处理已有截图。
- 作为登录用户，我希望历史记录同步到云端，以便换设备后继续查看。
- 作为用户，我希望可以注销账号并删除数据，以便控制个人信息。
- 作为进阶用户，我希望使用自己的 API Key 调用 AI，以便控制成本和供应商。

## 12. 业务规则

- 未登录用户可使用本地识别流程，但云端历史同步需要登录。
- 所有用户资源必须按 `user_id` 隔离。
- 图片和导出文件保存到 MinIO 或对象存储，MySQL 只保存 object key。
- 密码必须使用 BCrypt 哈希。
- Refresh Token 不得明文长期保存。
- 第三方 AI 调用前必须展示隐私提示并取得用户同意。
- 端侧 BYOK 可优先使用移动端安全存储保存 API Key；启用后端 Provider 代理时，API Key 必须由服务端加密保存并且只返回脱敏信息。

## 13. 云端同步规则

- 云端同步仅对登录用户开放。
- 当前采用服务端为准的最小同步策略。
- 客户端上传识别记录时，后端必须绑定当前用户，不接受客户端传入的任意 `user_id`。
- 客户端可按 `updated_after` 拉取增量记录。
- 删除记录采用软删除并通过 `deleted_at` 同步给客户端。
- 同步冲突当前由服务端 `updated_at` 较新的记录覆盖旧记录；复杂冲突合并留作后续增强。

## 14. 验收标准

- 核心产品能力矩阵中的 P0 能力均具备明确需求、API、数据、测试和隐私说明。
- 用户不能访问其他用户的 OCR 记录、文件对象和反馈详情。
- 账号注销和数据删除流程有可验证的删除或匿名化策略。
- BYOK AI 功能在文档中明确 API Key 存储边界、隐私提示和日志规则。
- 云端同步必须支持登录用户按更新时间增量拉取、软删除同步和用户隔离。
- 体验、进阶和可选平台能力不得在未确认范围前进入实现。
