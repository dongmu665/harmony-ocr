# 产品能力与交付路线

## 1. 文档目的

本文定义 HarmonyOS OCR 产品的能力分层、交付目标、范围边界和验收标准。各章节描述能力归属；当前开源快照的实际支持范围以本文明确说明、README、源码和自动化测试为准。

## 2. 能力分层与当前快照

核心 OCR 与账户能力、日常体验增强、OCR 扩展与 BYOK AI、运营与规模化能力表示产品能力的演进层次，不对应独立代码分支。当前仓库同时包含基础 OCR、体验增强、批量与 PDF、BYOK AI、会员额度和管理台能力；仍在路线中的能力会在对应章节明确列出。

## 3. 核心 OCR 与账户能力

### 3.1 交付目标

目标是形成可上线的 OCR 基础产品闭环：账号认证、图片获取、预览裁剪、真实 OCR、文本处理、历史记录、云端同步、文件对象存储、用户协议、隐私政策、账号注销和数据删除。

### 3.2 功能范围

| 模块 | 功能 |
| --- | --- |
| 账号认证 | 注册、登录、退出登录、刷新 Token、当前用户、账号注销 |
| OCR 图片流程 | 拍照识别、相册识别、图片预览、图片裁剪、真实 OCR、结果展示 |
| 文本处理 | 文本编辑、文本复制、格式清理 |
| 历史记录 | 保存、列表、详情、删除、收藏、搜索、云端同步 |
| 文件存储 | 图片上传、对象存储元数据、对象归属、删除或待清理 |
| 隐私合规 | 用户协议、隐私政策、数据删除、注销后 Token 失效 |
| 用户反馈 | HarmonyOS 客户端提交、服务端保存、管理端查看脱敏元数据并更新处理状态 |

### 3.3 后续扩展范围

后端增强 OCR、PaddleOCR 服务化、批量识别、PDF 导出、TTS、多语言识别、BYOK AI、会员额度、Web 管理后台、后端 AI Provider 代理、复杂多设备冲突合并属于后续扩展范围。

### 3.4 验收标准

1. 所有核心 P0 功能完成真实实现和测试。
2. 正式 OCR 路径必须使用 CoreVisionKit 或已配置的真实后端 Provider；Mock 只能用于自动化测试和本地开发，不能作为生产成功结果。端侧运行时不可用时允许使用真实后端 Provider 作为 fallback。
3. 后端 `mvn test` 通过。
4. 前端 `ohpm install` 与 `hvigorw --mode module -p module=entry@default assembleHap` 通过。
5. 真实 MySQL Flyway 迁移、真实 MinIO 联调通过。
6. 用户不能访问其他用户的记录、文件或反馈归属数据。
7. 账号注销、数据删除、Token 失效、对象存储清理策略通过。
8. 用户协议和隐私政策完整可访问。
9. 无 Blocker / High 缺陷。

### 3.5 运行边界

CoreVisionKit、相机和系统相册能力依赖兼容的 HarmonyOS 设备与运行时；模拟器缺少端侧 OCR 能力时，必须配置后端真实 OCR Provider 才能完成识别。仓库不捆绑第三方 OCR 服务、生产证书或外部 AI 凭据，部署者必须自行提供并验证这些运行依赖。

## 4. 日常体验增强

### 4.1 交付目标

在核心能力稳定后增强日常使用效率和本地体验。

### 4.2 功能范围

导出 TXT、分享识别文本、按日期筛选历史、按来源筛选历史、识别耗时显示、默认识别语言设置、是否自动清理格式设置、清理本地缓存、用户反馈体验增强。

### 4.3 后续扩展范围

批量 OCR、PDF 导出、TTS、多语言、置信度、BYOK AI、后端 AI 代理、会员系统和管理后台属于后续扩展范围。

### 4.4 验收标准

1. 核心能力全量回归通过。
2. 本层新增功能成功、异常、边界和兼容性测试通过。
3. 不破坏 OCR 主流程、历史记录和云端同步。
4. 系统分享、剪贴板、缓存清理等设备能力完成真机验证。

## 5. OCR 扩展与 BYOK AI

### 5.1 交付目标

提升 OCR 竞争力，并定义用户自带 API Key 的 AI 文本增强体验。

### 5.2 功能范围

批量图片识别、批量导出、PDF 导出、TTS、多语言识别、识别置信度、低置信度标注、图片旋转、去噪、倾斜校正、自定义 AI 供应商、BYOK API Key、连接测试、AI 纠错、摘要、翻译、智能排版、转 Markdown。

### 5.3 运营与规模化范围

后端统一代理 AI、后端加密保存用户 API Key、AI 调用额度、会员扣费、后台 Provider 管理属于运营与规模化能力。

### 5.4 验收标准

1. 核心能力与体验增强能力回归通过。
2. OCR 增强功能成功、失败、超时、大文件和弱网场景通过。
3. API Key 不写日志、不明文展示；当前后端托管模式只允许通过 HTTPS 提交并加密保存，未来纯端侧模式不得默认上传后端。
4. OCR 文本发给第三方 AI 前必须展示隐私提示并取得用户确认。
5. AI 输出不得覆盖原文，必须允许用户编辑和确认。
6. 默认不自动把 OCR 结果发送给第三方 AI。

## 6. 运营与规模化能力

### 6.1 交付目标

面向商业化、后台管理、后端 OCR 服务化、AI Provider 代理和规模化运行。

### 6.2 功能范围

后端增强 OCR、PaddleOCR 服务化、表格识别、PDF 多页识别、可搜索 PDF、云端文件夹管理、多设备同步、会员额度、OCR 次数统计、Web 管理后台、用户行为统计、后端 AI Provider 管理、后端代理 AI 请求、API Key 加密存储、AI 调用日志、额度统计、多供应商故障切换。

当前开源快照已实现后端 OCR Provider 接口、扫描型 PDF 与批量 OCR、可搜索 PDF 基础导出、会员额度、Web 管理台、用户 Provider 配置加密存储和后端 AI 代理。多 Provider 顺序切换目前仅具备 contract 与自动化测试，默认配置不会同时注册多个生产 Provider。PaddleOCR 独立服务、表格识别、云端文件夹、复杂多设备冲突合并、完整行为分析、生产级 KMS、支付结算、可配置 Provider chain 和规模化任务调度仍属于后续范围。

### 6.3 验收标准

1. 全量回归通过。
2. 性能、并发、长任务、失败重试测试通过。
3. 会员额度扣减在并发、重试和失败补偿下保持一致。
4. 管理后台权限、审计和操作隔离通过。
5. AI Provider 密钥加密、脱敏返回、日志脱敏和 SSRF 防护通过。
6. 数据备份和恢复完成演练。
